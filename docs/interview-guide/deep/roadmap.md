## 故事 1：动态 Pipeline 阶梯（L1-L5）

```
L1 受限模式 ✅ —— 工具按名从预注册清单选、失败即终止（已实现）
L2 自愈     —— 失败后拿结构化报告重新规划拓扑
L3 完全     —— 自建 tool（原语组合）+ 自建类型（schema 校验的 JSON 消息）
L4 沙箱执行 —— goja 语言级隔离跑 LLM 生成的代码
L5 工具生成 —— agent 走完开发者工作流：spec→实现→注册→跨会话复用
```

**阶梯的内在逻辑**：每级解锁的能力以上一级为地基——L5 的工具
执行体活在 L4 的沙箱里；L4 的沙箱策略（Policy）复用已实现的沙箱层。
**渐进式放权**：L1 只许"选"，L3 才许"造"，每放一级权都有对应的安全
闸门跟上。

## 故事 2：benchmark 自迭代闭环（最远的愿景）

```
开发 agent（改进者）
  ├─ 改业务 agent 的 prompt/工具/编排（被改进者）
  ├─ 改 benchmark 自身（发现盲区补 case）
  ├─ 改自己（自举）
  └─ 启动下一轮的独立环境实例
       ↓ 测量（隔离环境 + 固定 seed + 全事件落盘）
业务 agent
       ↓
结构化报告 → 保留/回滚/继续 → 循环到边际效应停止
```

**三条防线**（讲出来直接体现工程成熟度）：
1. **防过拟合**：benchmark 只增不删（开发 agent 同时改考题和考生有
   作弊压力——把考题改简单比把考生改强容易）+ held-out 集 + 人工抽检不可全撤
2. **环境隔离**：新实例拿独立会话/worktree——共享状态测出的提升是污染
3. **机器可判停止条件**：连续 N 轮提升 < ε / 预算耗尽——不能靠 agent "感觉"

## 故事 3：与竞品对比的方法论（差异定位）

| 对比对象 | 我们的判断 |
|---------|-----------|
| LangChain | 抽象层堆叠不开箱即用——组件生态路线 |
| eino | 造引擎（graph 编排 + RAG 组件），我们造整车（运行时）——路线差异非优劣 |
| LangGraph | agent 版 Temporal（长时有状态 + checkpoint + human-in-loop）——学零件不学产品 |
| Claude Code | 不是竞品是标杆——文件工具/权限/事件语义全面对标 |

**核心判断公式**（适用于一切"要不要做 X 功能"）：
- 拓扑是代码（编译期定）→ 函数调用就够；拓扑是数据（运行期定/要分享）→ 才需要图结构
- eino 的 graph 动态性拆解：数据分支不需要动态 / LLM 建图我们领先
  （dynpipeline）/ 热重载是基础设施职责——**逐场景拆解后"补 graph"不成立**

## 故事 4：安全设计的三闸门（L5 攻击面分析）

提问："agent 能自己写工具了，它写个恶意工具绕过沙箱怎么办？"

回答的层次（每层都能展开）：
```
攻击面：绕过不需要"突破"沙箱，只需要"不经过"沙箱
  路径1 工具组合放大（包一层 Bash 换名字）
  路径2 提示注入持久化（无害代码+恶意描述，借宿主权限行凶）
  路径3 供应链时间差（旧工具依赖的原语语义变了）

三闸门：
  ① 执行体准入——合法形态只有"原语组合"和"沙箱代码"两种，
    "原生执行体"在注册协议里物理不存在（不是禁止，是没有这个字段）
  ② 接口面净化——description/schema 过注入检测（执行体在沙箱里但
    "嘴"在系统里）
  ③ 权限低位+探针评估+能力只减不增+依赖变更降级

权限三层全景：进程权限层（人类签字区）/ 受裁射程层（Policy 逐 tool
裁决）/ 零权限层（纯计算）——新增系统能力的唯一通道 = agent 提案、
开发者写原语
```

## 能讲的"错误与修正"（可信度最高的素材）

1. Supervisor v1 队列方案废弃——为架构统一牺牲语义正确性，baggage
   补丁的存在说明模型选错了。改为控制流移交
2. 持久化 checkpoint 误判"不做"——忽视审批周期超进程生命周期
   （部署重启蒸发挂起三天的审批），用户纠正后收回
3. RAG 先想做成纯工具——忽视生产 RAG 的主流是前置固定管道（可靠性/
   成本可控），改为双形态
4. 探查报告的"fork 幻觉"——子代理声称 agent/ 目录是 eino fork，
   实测证伪（5 个自研文件 1109 行）。教训：转述前必验证
