# 深潜 7：上下文治理（context management）

> 位置：`compaction/`（压缩）+ `memory/` `sessionmem/` `extractmem/`（记忆）+ session 持久化
> 回答的问题：长对话怎么不撑爆上下文窗口、不烧穿 token？

## 三件套的分工

```
会话持久化（session）  —— 对话历史落盘，崩溃不丢（见 sessions.md）
压缩（compaction）     —— 单会话内历史太长时摘要收缩
记忆（memory）         —— 跨会话的持久知识 + 会话内的定期提取
```

## 压缩：四层 + 阈值触发 + Circuit Breaker

**触发**：上下文占用超阈值（默认 0.8）自动压缩。

**四层压缩**（由轻到重，逐层升级）：
```
L1 工具结果截断   —— 单个工具输出超 MaxResultSize 截断（工具级）
L2 旧消息裁剪     —— 中间轮次的 tool_result 折叠/移除，保留骨架
L3 历史摘要       —— LLM 把旧历史压成摘要段，替换原文
L4 全量重建       —— 极端情况整个上下文重写
```

**Circuit Breaker（熔断）**：压缩本身也调 LLM——如果连续压缩失败/
压缩后仍然超限（风暴循环：压了还超、超了再压），熔断器跳闸停止
自动压缩，转事件告警由宿主决策。**防止治理机制本身成为故障源**。

面试点：压缩是"有损"操作，摘要可能丢关键细节——所以工具结果截断
（L1，无损可控）优先于历史摘要（L3，有损）；且压缩后保留"最近 N 轮
原文 + 更早的摘要"的分层结构，而不是无差别全摘。

## 记忆系统三层

```
memory/     跨会话持久记忆（MemoryDir 目录文件制）
             —— agent 自己读写（"记住我的偏好"类信息跨会话可见）
sessionmem/ 会话内定期提取（PostSampling hook）
             —— 每轮采样后判断是否提取要点入会话记忆，
                长会话的关键事实沉淀
extractmem/ 结构化提取记忆（对齐 Claude Code 的 extract memory）
```

**为什么记忆和压缩是两件事**：压缩解决"窗口装不下"（摘要旧历史），
记忆解决"信息不该丢"（关键事实显式保存）。压缩是空间问题，记忆是
知识管理问题——混在一起会既压不好又记不准。

## 与预算系统的联动

budget/ + cost/：token 总预算、单会话预算、成本追踪（observer 的
OnTokenUsage 带美元成本）。超限熔断——**资源治理是上下文治理的
兄弟**：一个防"撑爆窗口"，一个防"烧穿钱包"。

## 面试可讲的取舍

- **逐条即时落盘 vs 整轮落盘**：崩溃窗口损失从整轮缩到单条，代价是
  每条消息一次 IO——会话粒度下可接受
- **压缩触发在"轮间"而非"轮中"**：轮中压缩会破坏正在进行的工具
  调用序列（tool_use 和 tool_result 必须成对），轮间是安全切割点
- **摘要用同一个 provider 还是独立小模型**：当前同 provider 可配
  独立 prompt 文件（promptDir 外部覆盖），生产建议独立便宜模型——
  摘要质量要求低于主任务
